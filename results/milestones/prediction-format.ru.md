# Формат предсказаний

Этот документ определяет контракт файлов предсказаний для моделей, оцениваемых в benchmark `vepkar-morph-disambig`.

Файл предсказаний ранжирует уже существующие кандидатные морфологические разборы корпусных словоупотреблений. Он не добавляет новых кандидатов, не изменяет исходную разметку и не содержит gold-меток.

## Область задачи

Задача benchmark — ранжирование морфологических кандидатов:

```text
словоупотребление в предложении
        +
его существующие кандидатные разборы
        ↓
ранжировать кандидаты
        ↓
выбрать wordform_id + gramset
```

Кандидат идентифицируется тройкой:

```text
(word_id, wordform_id, gramset)
```

Исходное поле `relevance` не входит в файл предсказаний. Оно используется только при построении benchmark, чтобы определить выбранный экспертом gold-кандидат (`relevance = 2`).

## Один файл — один split

Один файл предсказаний содержит полное ранжирование для одной
части оценки: `dev` или `test`. Смешивать части в одном файле нельзя.

Значение split не повторяется в каждой строке CSV. Его передают валидатору аргументом:

```bash
python src/cli.py validate-predictions \
  --predictions /some/path/predictions.csv \
  --split test
```

Валидатор получает список оцениваемых словоупотреблений из общего файла `splits_<tag>.csv` и строгих benchmark-экземпляров.

Временные результаты модели могут лежать в любом месте. Выбранный официальный результат хранится в `results/milestones/`.

## Схема CSV

Файл предсказаний обязан содержать ровно пять столбцов и именно в таком порядке:

```csv
word_id,wordform_id,gramset,rank,score
```

| Столбец | Тип | Значение |
|---|---|---|
| `word_id` | Положительное целое | Идентификатор оцениваемого корпусного словоупотребления |
| `wordform_id` | Положительное целое | Идентификатор кандидатной словоформы словаря |
| `gramset` | Непустая строка | Набор грамматических признаков кандидата |
| `rank` | Положительное целое | Позиция кандидата; `1` — лучший кандидат |
| `score` | Конечное число | Внутренняя оценка кандидата моделью; чем выше, тем лучше |

Пример:

```csv
word_id,wordform_id,gramset,rank,score
501,9001,SG+NOM,1,125
501,9001,SG+ACC,2,17
501,9002,PL+GEN,3,3
502,7712,SG+NOM,1,42
502,7712,SG+GEN,2,8
```

Это один файл с предсказаниями для многих словоупотреблений, а не отдельный файл для каждого `word_id`.

## Правила полноты

Для каждого оцениваемого `word_id` файл предсказаний должен содержать каждого кандидата строгого benchmark ровно один раз.

```text
Строгий benchmark, word_id=501:
  A = (9001, SG+NOM)
  B = (9001, SG+ACC)
  C = (9002, PL+GEN)

Файл предсказаний для word_id=501:
  A, B, C
```

Недопустимы следующие случаи:

```text
- В файле присутствует только лучший кандидат.
- Отсутствует кандидат из benchmark.
- Добавлен кандидат, которого нет в benchmark.
- Одна и та же тройка (word_id, wordform_id, gramset) встречается более одного раза.
- В файл попало словоупотребление, не принадлежащее указанному split.
```

Файл не должен содержать `relevance`, gold-метку или нового кандидата, придуманного моделью.

## Rank и score

Для словоупотребления с `N` кандидатами ранги должны быть ровно такими:

```text
1, 2, 3, ..., N
```

Недопустимые ранги:

```text
1, 1, 3    повтор rank
1, 3, 4    пропущен rank=2
0, 1, 2    rank начинается не с 1
```

`score` должен быть конечным числом и согласовываться с rank:

```text
rank=1 score >= rank=2 score >= rank=3 score >= ...
```

Равные score допустимы, но ranks всё равно должны быть уникальными и полными. Модель обязана детерминированно разрешать равенство.

Значения `score` разных методов не сопоставимы напрямую.
Качество методов сравнивают по метрикам ранжирования.

Другие модели могут использовать собственные внутренние оценки, но их итоговый CSV всё равно обязан задавать полное однозначное ранжирование.

## Валидация

`validate-predictions` проверяет, что файл совместим с выбранной частью benchmark. Проверяются:

```text
- Точный заголовок и порядок столбцов.
- Требуемые типы и непустые gramset.
- Конечные числовые score.
- Принадлежность кандидатов строгому benchmark.
- Полнота списка кандидатов для каждого word_id.
- Отсутствие повторных candidate tuples.
- Принадлежность каждого word_id указанному split.
- Точные ranks 1..N для каждого word_id.
- При увеличении rank значение score не возрастает.
```

Валидация отвечает на вопрос:

```text
«Структурно полон ли этот файл и совместим ли он с benchmark?»
```

Она не отвечает на вопрос:

```text
«Точна ли эта модель?»
```

Команда `evaluate-predictions` проверяет файл и вычисляет
`Top-1 accuracy`, `MRR` и `Top-3 accuracy`.
[Порядок оценки](../../docs/evaluation.ru.md).

## Сохранение результатов

Проверенный файл предсказаний может быть вручную принят
как значимый результат. Его содержимое должно соответствовать
описанному выше формату.

[Правила хранения и оформления результатов](README.ru.md).
