# Сравнение запусков T1.1

Здесь хранятся выбранные построчные сравнения готовых результатов.
Файлы сгруппированы по версии исходных данных.

## Запуск сравнения

Выполняйте команду из корня репозитория:

```bash
.venv/bin/python src/cli.py compare-t1-runs \
  --run-dirs \
  results/milestones/v2026.09/t1.1-C0.1-2026-10-29 \
  results/milestones/v2026.09/t1.1-C1-2026-10-27 \
  results/milestones/v2026.09/t1.1-C10-2026-10-29
```

Передайте минимум два разных каталога. Каждый должен содержать
`metrics.json` и ровно один файл предсказаний: `dev.csv` или `dev.csv.zst`.
Рабочие и экспортированные результаты можно смешивать.

Для проверки и получения экспертных ответов используется локальный
корпус и опубликованное разбиение `data/derived/splits_<tag>.csv`.
Расположение корпуса берётся из `t1.local.toml`, если оно задано,
либо из стандартного `data/dictorpus-data`.

Команда проверяет предсказания и сравнивает все пары:

```text
Три запуска:          Полученные сравнения:

C=0.1                 C=0.1 ↔ C=1
C=1          --->     C=0.1 ↔ C=10
C=10                  C=1   ↔ C=10
```

В терминале выводятся источники, таблица пар, изменения метрик
и лидеры по каждому показателю. Для четырёх и более источников
лидеры показываются отдельной таблицей, кроме случая, когда один
запуск единолично лучший по всем трём метрикам.

## Направление A → B

В каждой паре B выбирается по приоритету:
Top-1, затем MRR, затем Top-3. Показатели сравниваются без округления.
При полном равенстве первый вход становится A, второй — B.

```text
A ─── сравниваем ответы ───> B

Исправлено: A ошибся, B выбрал экспертный разбор.
Испорчено:  A выбрал экспертный разбор, B ошибся.

Дельты = показатель B − показатель A.
```

B может уступать A по другой метрике или отдельной языковой разновидности.
Положительность всех дельт не предполагается.

## Выходные файлы

Для каждой пары создаётся CSV:

```text
work/comparisons/<tag>/<метод A>-C<значение A>__vs__<метод B>-C<значение B>.csv
```

Например:

```text
t1.1-C0.1__vs__t1.1-C10.csv
```

Метод и C берутся из метаданных запусков. Даты и суффиксы каталогов
в имя сравнения не входят. Конкретные пути A/B указаны в отчёте терминала.

Пути файлов перечисляются в разделе `Outputs`.
Существующие файлы не перезаписываются. Если разные пары получают
одинаковое короткое имя, команда сообщает о столкновении до записи.

## Содержание CSV

Одна строка соответствует одному dev-словоупотреблению.
Включены все употребления, а не только изменившиеся.
Правильный разбор определяется полной парой `(wordform_id, gramset)`.

| Поля | Содержание |
|---|---|
| `language`, `word_id`, `word` | Языковой код, идентификатор и написание слова |
| `candidate_count` | Число кандидатов |
| `gold_wordform_id`, `gold_gramset` | Экспертный разбор |
| `a_top1_wordform_id`, `a_top1_gramset` | Первый кандидат в A |
| `b_top1_wordform_id`, `b_top1_gramset` | Первый кандидат в B |
| `a_gold_rank`, `b_gold_rank` | Позиция экспертного разбора в каждом рейтинге |
| `top1_changed` | `1`, если первый кандидат изменился, иначе `0` |
| `outcome` | Категория изменения |
| `delta_rr` | Изменение обратной позиции gold: `1/b_gold_rank − 1/a_gold_rank` |

Значения `outcome`:

- `both_correct` — оба ответа правильные;
- `corrected` — ошибка A исправлена в B;
- `regressed` — правильный ответ A испорчен в B;
- `both_wrong_same` — оба ответа неправильные и одинаковые;
- `both_wrong_changed` — оба ответа неправильные, но различаются.

Среднее `delta_rr` по всем строкам равно ΔMRR.

## Сохранённые сравнения

```text
work/comparisons/<tag>/*.csv
              |
              | выбранные файлы копируют и сжимают вручную
              v
results/comparisons/<tag>/*.csv.zst
```

Рабочие CSV остаются локальными. Команда сравнения не переносит
их в `results/` и не добавляет файлы в Git.
