# vepkar-morph-disambig

Проект посвящён контекстному ранжированию кандидатов морфологического
разбора слова в корпусе ВепКар: выбору словоформы и набора
грамматических признаков из предложенных вариантов.

В репозитории представлены три направления исследования:

- `src/t1_features/` — модели на признаках;
- `src/t2_context/` — контекстные модели;
- `src/t3_transfer/` — перенос обучения между языковыми разновидностями.

Общие алгоритмы находятся в `src/core/`, обработчики команд —
в `src/commands/`. Точка входа командной строки — `src/cli.py`.

## Подготовка окружения

Требуются Python 3.11 или новее и Git.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install numpy pandas zstandard scikit-learn scipy joblib pytest
python -m pytest -q
```

## Работа с данными

Получить исходные данные из
[dictorpus-data](https://github.com/componavt/dictorpus-data/):

```bash
python src/cli.py fetch-data v2026.09
```

Проверить корпус:

```bash
python src/cli.py inspect-data krl
```

Для экспериментов с `v2026.09` используйте опубликованный файл
`data/derived/splits_v2026.09.csv`. Повторно создавать разбиение
перед запуском модели не нужно.

Языковые коды: `vep` — вепсский язык; `krl`, `olo`, `lud` —
собственно карельское, ливвиковское и людиковское наречия
карельского языка соответственно.

[Набор для оценки, очередь ручной проверки и разбиение](data/derived/README.ru.md).

## Оценка качества

Реализован частотный базовый метод: кандидаты ранжируются по частоте
экспертных разборов в обучающей части. Качество оценивается отдельно
на наборах `dev` и `test`.

Для частотного метода реализована диагностика на `dev`:
сопоставление с экспертными ответами, построчная таблица CSV
и краткая числовая сводка.

[Порядок запуска и вычисления метрик](docs/evaluation.ru.md).
[Результаты частотного метода](docs/frequency_baseline.ru.md).

## T1: модель на признаках

T1.1 ранжирует кандидатов с помощью логистической регрессии.
Используются грамматические признаки кандидата, суффиксы слова
и ближайшие соседние слова. Частоты разборов в признаки не входят.
Одна общая модель обучается на `train` четырёх языковых разновидностей;
предсказания и оценка пока выполняются только для `dev`.

Выполняйте команды из корня репозитория с активированным окружением
`.venv`, после получения исходных данных.

### Подготовка и выполнение запуска

Подготовить новый запуск с `C=1.0`:

```bash
python src/cli.py prepare-t1-run --C 1.0
```

Скопируйте путь из строки `Run directory:` в переменную `RUN_DIR`:

```bash
RUN_DIR="путь из строки Run directory:"
python src/cli.py train-t1 --run-dir "$RUN_DIR"
python src/cli.py predict-t1 --run-dir "$RUN_DIR"
python src/cli.py evaluate-t1-run --run-dir "$RUN_DIR"
```

В каталоге запуска последовательно появляются `run.json` с условиями
эксперимента, `model.bundle` с моделью, `dev.csv` с предсказаниями
и `metrics.json` с метриками. Существующие результаты не перезаписываются.

При стандартных путях настройка не требуется. Другие пути можно задать
в необязательном `t1.local.toml`; пример — `t1.local.example.toml`.
После подготовки запуска команды берут условия из `run.json`.

Для другого C [подготовьте новый запуск](#подготовка-и-выполнение-запуска),
указав нужное значение в `--C`. Из вывода команды `prepare-t1-run`
скопируйте путь после `Run directory:` и присвойте его переменной
`RUN_DIR`. Затем выполните обучение, предсказание и оценку для этого запуска.

Подбор C проводится на `dev`; набор `test` для выбора настроек не используется.

### Запуск одной командой

Из корня репозитория выполните:

```bash
bash scripts/t1-run-tools.sh 0.1
```

Помощник создаёт новый запуск с указанным C и последовательно выполняет
подготовку, обучение, предсказание и оценку. Без аргумента используется C=1.0.

Активировать `.venv` не требуется: используется интерпретатор проекта
`.venv/bin/python`. Настройки путей берутся из `t1.local.toml`,
если он есть.

Вывод команд остаётся в терминале; журналы не сохраняются.
При ошибке помощник останавливается. Для продолжения используйте
[отдельные команды](#подготовка-и-выполнение-запуска)
с каталогом остановленного запуска.

Экспорт результата выполняется отдельно.

### Экспорт результата

Для экспорта завершённого запуска скопируйте путь нужного запуска
из строки `Run directory:` и присвойте его переменной `RUN_DIR`:

```bash
RUN_DIR="путь из строки Run directory:"
python src/cli.py export-t1-milestone --run-dir "$RUN_DIR"
```

Команда создаёт отдельный комплект результата:

```text
work/runs/<run>/
        |
        v
results/milestones/<tag>/<run>/
    README.md       — описание запуска и метрики;
    metrics.json    — копия метрик и условий эксперимента;
    dev.csv.zst     — сжатые предсказания для dev.
```

Здесь `<run>` — имя каталога запуска, `<tag>` — версия исходных данных,
указанная в `metrics.json`, например `v2026.09`.

Путь к созданному комплекту выводится в строке `Milestone directory:`.
Исходный запуск остаётся без изменений.
Существующий каталог результата не перезаписывается.
