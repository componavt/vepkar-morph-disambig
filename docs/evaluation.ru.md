# Оценка качества

Этот документ описывает построение, проверку и оценку файла предсказаний
для `dev` или `test`.

## Перед запуском

Выполняйте команды из корня репозитория с активированным окружением
`.venv`. Исходные данные должны быть получены, а файл разбиения —
подготовлен; команды приведены в [README](../README.ru.md).

Для текущего набора используется `data/derived/splits_v2026.09.csv`.
Описание разбиения — в
[data/derived/README.ru.md](../data/derived/README.ru.md).

## Полный порядок запуска

Пример для `test`:

```bash
python src/cli.py frequency-baseline \
  --split test \
  --output /tmp/vepkar-frequency-test-v2.csv

python src/cli.py validate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test

python src/cli.py evaluate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test
```

Для `dev` замените `--split test` на `--split dev` и используйте
другой выходной файл, например `/tmp/vepkar-frequency-dev-v2.csv`.

`frequency-baseline` ранжирует все кандидаты каждого словоупотребления
по частоте экспертных разборов в `train`, записывает CSV и проверяет его.
Экспертные ответы `dev` и `test` для обучения не используются.

Существующий выходной файл не перезаписывается. Для повторного запуска
выберите новый путь или удалите прежний файл, если он больше не нужен.
Файлы в `/tmp/` предназначены для временного хранения.

`validate-predictions` проверяет полноту и допустимость предсказаний.
`evaluate-predictions` выполняет такую же проверку перед вычислением
метрик.

Проверка и оценка не изменяют файл предсказаний и не сохраняют
новых результатов.

[Формат CSV и требования к предсказаниям](../results/milestones/prediction-format.ru.md).

## Метрики

Каждое оцениваемое словоупотребление имеет одинаковый вес.
Правильный кандидат определяется точной парой
`(wordform_id, gramset)`, выбранной экспертом.

Оценивается ранжирование уже имеющихся кандидатов: правильным
считается кандидат, выбранный экспертом. Новые кандидаты не создаются.

- `Top-1 accuracy` — доля словоупотреблений, для которых правильный
  кандидат занимает первое место.
- `MRR` — среднее значение обратной позиции правильного кандидата:
  первое место даёт 1, второе — 1/2, третье — 1/3.
- `Top-3 accuracy` — доля словоупотреблений, для которых правильный
  кандидат входит в первые три позиции. Если кандидатов меньше трёх,
  учитываются все имеющиеся позиции.

Метрики выводятся как доли от 0 до 1 с четырьмя знаками после запятой.
Округляется только вывод, а не исходные вычисления.

## Сравнение методов

Для корректного сравнения нужны одна версия исходных данных,
один файл разбиения, одинаковые оцениваемые словоупотребления
и наборы кандидатов, одинаковые метрики и способ взвешивания.

Настройки и варианты метода выбирают на `dev`. Набор `test`
используют для итоговой оценки, а не для выбора настроек.
Результаты двух частей приводят отдельно.
