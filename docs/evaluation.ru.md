# Оценка качества

В этом документе описан полный порядок получения метрик для одного предсказания на контрольном наборе `dev` или `test`.

## Общий порядок

Оценка выполняется в три шага:

1. построить предсказания для выбранного набора;
2. проверить соответствие предсказаний строгому контракту benchmark;
3. вычислить метрики ранжирования.

```bash
python src/cli.py frequency-baseline \
  --split test \
  --output /tmp/vepkar-frequency-test-v2.csv

python src/cli.py validate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test

python src/cli.py evaluate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test
```

## Построение предсказаний

Команда `frequency-baseline` строит ранжирование кандидатов по частоте их экспертных анализов в обучающем наборе. Она не использует данные `dev` или `test` для обучения.

```bash
python src/cli.py frequency-baseline \
  --split test \
  --output /tmp/vepkar-frequency-test-v2.csv
```

Параметры:

- `--split` — контрольный набор: `dev` или `test`;
- `--output` — путь к создаваемому файлу предсказаний.

Команда создаёт CSV-файл со столбцами:

```text
word_id,wordform_id,gramset,rank,score
```

Для каждого слова записываются все его строгие кандидаты. Позиция `rank` начинается с единицы; `score` отражает частоту кандидата в обучающих данных.

## Проверка предсказаний

Перед вычислением метрик предсказания необходимо проверить.

```bash
python src/cli.py validate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test
```

Проверка убеждается, что:

- файл содержит все слова выбранного набора;
- для каждого слова приведены все его строгие кандидаты;
- позиции кандидатов образуют полную перестановку от `1` до числа кандидатов;
- порядок позиций согласован со значениями `score`;
- в файле нет повторов и лишних кандидатов.

Успешная проверка выглядит так:

```text
Predictions validation: OK
Split: test
Validated: 2,801 word instances, 6,950 candidate rows
```

## Вычисление метрик

```bash
python src/cli.py evaluate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test
```

Команда оценивает только слова выбранного набора и выводит три показателя:

```text
Prediction evaluation: OK
Predictions: /tmp/vepkar-frequency-test-v2.csv
Split: test
Evaluated: 2801 word instances, 6950 candidate rows

Metric             Value
Top-1 accuracy     0.7319
MRR                0.8584
Top-3 accuracy     0.9921
```

## Правила сравнения моделей

Сравнивать результаты разных методов можно только при выполнении всех условий:

- один и тот же контрольный набор: `dev` или `test`;
- один и тот же строгий набор кандидатов для каждого слова;
- одинаковые метрики: `Top-1 accuracy`, `MRR` и `Top-3 accuracy`;
- одинаковый способ взвешивания: каждое слово учитывается один раз;
- раздельная оценка `dev` и `test`: их результаты нельзя объединять.

Новый метод сначала оценивается на `dev`. Итоговое сравнение с базовым методом выполняется на `test` и проводится один раз.

## Результаты базового прогона

Ниже приведены результаты частотного базового метода. Обучение выполнялось только на обучающем наборе; наборы `dev` и `test` использовались исключительно для оценки.

| Набор | Слов | Кандидатов | Top-1 accuracy | MRR | Top-3 accuracy |
|---|---:|---:|---:|---:|---:|
| dev | 2,826 | 6,961 | 0.7095 | 0.8454 | 0.9890 |
| test | 2,801 | 6,950 | 0.7319 | 0.8584 | 0.9921 |

Эти результаты служат отправной точкой для сравнения с последующими методами снятия морфологической омонимии.
