# Оценка качества

Этот документ описывает запуск частотного метода на `dev` или `test`,
общие метрики и диагностику частотного метода на `dev`.
Запуск T1 описан в [README](../README.ru.md#t1-модель-на-признаках).

## Перед запуском

Выполняйте команды из корня репозитория с активированным окружением
`.venv`. Получите исходные данные по
[инструкции в README](../README.ru.md#работа-с-данными).

Для оценки используйте опубликованное разбиение
`data/derived/splits_v2026.09.csv`.
Его устройство и способ подготовки описаны в
[разделе о разбиении](../data/derived/README.ru.md#разбиение-traindevtest).

## Порядок запуска частотного метода

Пример для `test`:

```bash
python src/cli.py frequency-baseline \
  --split test \
  --output /tmp/vepkar-frequency-test-v2.csv

python src/cli.py validate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test

python src/cli.py evaluate-predictions \
  --predictions /tmp/vepkar-frequency-test-v2.csv \
  --split test
```

Для `dev` замените `--split test` на `--split dev` и используйте
другой выходной файл, например `/tmp/vepkar-frequency-dev-v2.csv`.

`frequency-baseline` ранжирует все кандидаты каждого словоупотребления
по частоте экспертных разборов в `train`, записывает CSV и проверяет его.
Экспертные ответы `dev` и `test` для обучения не используются.

Существующий выходной файл не перезаписывается. Для повторного запуска
выберите новый путь или удалите прежний файл, если он больше не нужен.
Файлы в `/tmp/` предназначены для временного хранения.

`validate-predictions` проверяет полноту и допустимость предсказаний.
`evaluate-predictions` выполняет такую же проверку перед вычислением
метрик.

Проверка (`validate-predictions`) и оценка (`evaluate-predictions`) не изменяют файл
предсказаний и не сохраняют новых результатов.
Команда T1 `evaluate-t1-run` сохраняет метрики в `metrics.json`.

[Формат CSV и требования к предсказаниям](../results/milestones/prediction-format.ru.md).

## Метрики

Каждое оцениваемое словоупотребление имеет одинаковый вес.
Правильный кандидат определяется точной парой
`(wordform_id, gramset)`, выбранной экспертом.

Оценивается ранжирование уже имеющихся кандидатов: правильным
считается кандидат, выбранный экспертом. Новые кандидаты не создаются.

- `Top-1 accuracy` — доля словоупотреблений, для которых правильный
  кандидат занимает первое место.
- `MRR` — среднее значение обратной позиции правильного кандидата:
  первое место даёт 1, второе — 1/2, третье — 1/3.
- `Top-3 accuracy` — доля словоупотреблений, для которых правильный
  кандидат входит в первые три позиции. Если кандидатов меньше трёх,
  учитываются все имеющиеся позиции.

Метрики выводятся как доли от 0 до 1 с четырьмя знаками после запятой.
Округляется только вывод, а не исходные вычисления.

## Диагностика частотного метода

После построения предсказаний для `dev` выполните:

```bash
python src/cli.py diagnose-frequency-baseline \
  --predictions /tmp/vepkar-frequency-dev-v2.csv \
  --output /tmp/vepkar-frequency-dev-diagnostics.csv
```

Команда работает только с `dev`. Она проверяет предсказания
и подтверждает совпадение кандидатов, рангов и оценок
с частотным baseline для тех же данных и разбиения.

На вход подаётся несжатый predictions CSV. Архив `.csv.zst`
предварительно распаковывают. Выходной каталог должен существовать;
существующий файл или символическая ссылка не заменяются.

Диагностический CSV содержит одну строку на каждое оцениваемое
словоупотребление, включая правильные ответы:

```csv
language,word_id,word,candidate_count,gold_wordform_id,gold_gramset,top1_wordform_id,top1_gramset,gold_rank,gold_train_frequency,top1_train_frequency
```

`word` переносится из нормализованного корпусного поля.
`gold_*` описывают экспертный кандидат, `top1_*` — кандидат
на первом месте. `gold_rank = 1` означает правильный Top-1.
Кандидаты сравниваются по точной паре `(wordform_id, gramset)`.

Частоты относятся к экспертным выборам этой пары в `train`,
а не к числу появлений написания слова в корпусе.

После сохранения CSV команда выводит общие показатели,
распределение позиции экспертного кандидата, показатели нулевых
частот и равенств, а также таблицы по подкорпусу и числу кандидатов.
При нулевом знаменателе доля обозначается `N/A`.

Диагностическая таблица не является файлом предсказаний:
она содержит экспертные сведения и предназначена для анализа ошибок.

## Сравнение методов

Для корректного сравнения нужны одна версия исходных данных,
один файл разбиения, одинаковые оцениваемые словоупотребления
и наборы кандидатов, одинаковые метрики и способ взвешивания.

Настройки и варианты метода выбирают на `dev`. Набор `test`
используют для итоговой оценки, а не для выбора настроек.
Результаты двух частей приводят отдельно.

[Результаты частотного базового метода](frequency_baseline.ru.md).
